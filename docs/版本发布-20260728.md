## 背景与目标

将 Android 应用版本升级为 1.4.0，生成正式签名的 Release APK，并通过 GitHub Releases 对外发布。

## 架构理解

- 核心模式：Gradle `defaultConfig` 统一维护应用版本，`release` 构建类型复用既有签名配置。
- 相关模块：Android 应用构建配置、Git 提交与 GitHub Release。
- 已识别设计模式：沿用现有版本号与签名配置，不引入新抽象。
- 假实现区域：未发现。
- 用户路径：用户从 GitHub Releases 下载 1.4.0 Release APK。

## 方案决策

将 `versionCode` 从 130 调整为 140，将 `versionName` 从 1.3.0 调整为 1.4.0。版本标签和 Release 名称统一使用 `v1.4.0`，避免继续使用省略补丁版本的标签。Release 说明列出本版本新增的中英文切换、消息定时删除及相应体验改进。

### 引入/复用的设计模式

无新增模式；复用项目现有 Gradle Release 构建和签名方式。

### 预期改动方向

- 更新 Android 应用版本号。
- 构建并校验正式签名 APK。
- 使用 Tyler 作为本次版本提交的 Git 作者和提交者姓名。
- 推送代码和版本标签，并创建包含 APK 与版本说明的 GitHub Release。

### 副作用与风险

- Release APK 依赖现有密钥文件和密码可用。
- GitHub Release 的发布账号由 GitHub 登录凭据决定，不能通过 Git 提交姓名改变。
