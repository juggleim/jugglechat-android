# 版本信息展示错误修复文档

**日期:** 20260728
**严重程度:** 🟡 影响体验
**状态:** 已修复

## 问题描述

应用已升级至 1.4.0，但“我的”页面仍显示历史版本 2.5.1。

## 根因分析

- L2 直接原因：`MyProfileFragment` 初始化版本行时直接传入硬编码字符串 `2.5.1`。
- L3 根因：版本展示没有连接 Gradle 写入安装包的版本元数据，发布升版不会同步界面占位值。
- L4 系统性:
  - 代码层面：当前仅发现这一处硬编码版本展示。
  - 设计层面：发布校验只检查 APK 元数据，没有覆盖应用内版本信息页面。
  - 演化层面：历史占位实现未在版本功能完成后替换。

## 推理过程(关键节点)

→ 确认 APK 和设备安装版本均为 1.4.0 → 搜索界面版本来源 → 定位 `MyProfileFragment` 的 2.5.1 硬编码 → 改为读取当前安装包元数据 → 真机页面验证显示 1.4.0。

## 修复方案

**选择:** 正确修复
**理由:** 安装包元数据是应用版本的唯一事实源，后续 Gradle 升版可自动同步页面。
**改动范围:** “我的”页面版本行及中英文未知版本兜底文案。

## 实现说明

版本行通过 PackageManager 读取当前包的 `versionName`，读取异常时记录结构化日志并展示本地化“未知”；版本行不再显示可点击箭头或“功能开发中”提示。

## 回归风险与测试建议

- 回归风险：改动仅影响版本行取值和交互，已隔离。
- 建议测试：每次发布后同时核对 APK 元数据、设备包信息和“我的”页面版本文案。

## 反直觉洞察

APK 版本正确并不能保证应用内版本页面正确；发布检查需要覆盖用户可见的二次展示。
