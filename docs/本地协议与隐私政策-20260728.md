# 本地协议与隐私政策设计文档

**日期:** 20260728
**复杂度:** Medium
**状态:** 已完成

## 背景与目标

将用户协议和隐私政策随 APK 内置，提供简体中文、英文两个版本，并让登录、注册和个人页入口按 App 当前语言展示对应内容。

## Tension Scan 结论

- 原 SnailChat 文本包含微信注册、广告、支付和定位等当前 Android App 未体现的能力，不能只替换品牌后直接使用；本次按应用实际账号、消息、媒体、通话和权限范围收敛内容。
- 协议属于需长期审计的发布内容，应作为独立资源文件进入版本管理，而不是继续依赖可随时变化的远程页面。

## 架构理解

- 核心模式：三个入口统一通过 `WebViewPageActivity` 展示协议页面。
- 相关模块：应用壳层、语言管理、本地静态资源。
- 已识别设计模式：复用现有 WebView 页面作为统一入口，本地资源作为内容源。
- 假实现区域：当前协议 URL 指向 SnailChat 外部站点，内容和 App 品牌、语言状态不一致。
- 用户路径：用户从登录、注册或“我的”页面打开协议，无网络时也能看到与 App 当前语言一致的完整内容。

## 方案决策

在 `res/raw` 中保存中英文用户协议和隐私政策四份 HTML。`WebViewPageActivity` 只接收文档类型，根据 `LanguageManager.currentLocale()` 选择资源并以内存 HTML 加载，关闭 JavaScript、DOM 存储、文件访问和网络访问。

不拆分新的协议加载类：资源选择和读取仅被 `WebViewPageActivity` 使用，保留为该页面的私有逻辑更内聚。

### 引入/复用的设计模式

复用现有统一承载页，不引入新设计模式。

### 预期改动方向

- 新增四份中英文协议 HTML 资源。
- 将外部 URL 导航改为本地文档类型导航。
- 强化 WebView 的本地内容安全配置和读取失败处理。
- 保持现有所有协议入口和页面标题不变。

### 副作用与风险

- 协议更新必须随 App 发版，不再能通过远程页面即时修改。
- 本次文本依据当前代码能力整理，正式商用前仍需法务复核运营主体、联系方式、数据留存周期和第三方 SDK 清单。
