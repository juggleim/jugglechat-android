# 多语言约定

## 资源

`values/` 是**英文基准**（default），`values-zh/` 是简体中文；两边 key 必须一一对应、占位符一致。文案按模块分文件：`strings`（通用/消息/通话）、`strings_auth`、`strings_profile`、`strings_settings`、`strings_group`、`strings_social`、`strings_chat`。支持的语言在 `res/xml/locales_config.xml` 声明，manifest 通过 `android:localeConfig` 引用（Android 13+ 系统设置也能切）。

`app_name` 中英不同：英文 `JuggleChat`、中文 `链语`。

用户协议与隐私政策是独立 HTML 内容，放在 `res/raw/*_en.html` 与 `res/raw/*_zh.html`；由 `LanguageManager.currentLocale()` 显式选择，不能依赖远程页面或 WebView 的系统语言。

## 取串

* Activity / Fragment / 有 Context 的 View：直接 `getString(R.string.x)`。
* **静态工具类、消息模型（`chat/message/*`）、Adapter、Service：必须走 `i18n/AppRes.string(...)`**。这些场景拿到的是 Application/Service 的 Resources，在 API 33 以下不跟随 per-app locale，直接 `getString` 会取到系统语言的文案。
* 不允许把文案存进 `static final` 常量——常量在类加载时求值，语言切换后不会更新。

## 切换

语言选择由 `i18n/LanguageManager` 管理：存在 SharedPreferences（`my_settings.app_language`，空串表示跟随系统），生效走 `AppCompatDelegate.setApplicationLocales`，AppCompat 会自动重建所有 Activity。`Application#onCreate` 调用 `LanguageManager.init`，必须在任何界面创建前完成。入口在【我 → 通用设置 → 语言】(`app/LanguageSettingsActivity`)。

## 不本地化的字符串

* 服务端错误 `message`：界面统一展示本地化通用文案，原始 message 走 `LogUtils.serverError(feature, event, code, message)` 落日志（tag `ServerError`）。
* 服务端协议取值：如 `FeedbackActivity` 的反馈分类 `个人反馈 / 举报投诉`、搜索类型标识 `contact / group / record`，是数据不是文案。
* 日志文案与开发者异常信息。

## 语言相关逻辑

排序 `Collator` 用 `LanguageManager.currentLocale()`，不要写死 `Locale.CHINA`；星期/今天/昨天等时间文案走资源，不要在代码里拼中文。
